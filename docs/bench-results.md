# Benchmark

Generated by `npm run bench` on 2026-11-22.

Local single-machine run: 20 × 13th Gen Intel(R) Core(TM) i7-13650HX, 8 GB RAM, Node v22.23.5, PostgreSQL 18.7, Redis 7.4.12, linux. The load generator, the service, Postgres and Redis shared this machine, so use these numbers to compare designs. They are not capacity figures.

Data: 5,000 products, 200,000 reviews, 300,000 order items. The slow read ranks a product in its category and has no artificial delay.

## Stampede

Three processes. One hot key goes cold everywhere, then 300 requests arrive at once. Five rounds.

| Protection | Origin loads in each round | p50 (ms) | p99 (ms) |
| --- | --- | --- | --- |
| Baseline: key already warm, no stampede | 0, 0, 0, 0, 0 | 6.5 | 14.3 |
| No protection | 289, 258, 192, 300, 300 | 56.4 | 107 |
| Coalescing in each process | 3, 3, 3, 3, 3 | 11.3 | 19.0 |
| Coalescing and a Redis lock | 1, 1, 1, 1, 1 | 19.5 | 23.6 |
| Also serving stale while refreshing | 1, 1, 1, 1, 1 | 7.0 | 24.9 |

The baseline row is the cost of this test itself: 300 simultaneous requests generated and answered on one machine. Latency above it is the stampede's. In the last row the entry is past its soft TTL and not deleted, because serving stale needs an old value to serve.
